# OCR for Kannada–English Shop Signs

MCA internship project: *Optical Character Recognition – Quantification with Various ML
Approaches*. The project recognises cropped word images from Kannada and English shop signs using
four models, all trained from scratch:

| | Model | Requires segmentation |
|---|---|---|
| A | HOG + SVM | yes |
| B | HOG + Random Forest | yes |
| C | Small CNN | yes |
| D | CRNN (CNN + BiLSTM + CTC) | no |

Models A–C share a single conventional segmenter (Otsu thresholding, connected components and
projection profiles), applied unchanged to both scripts. The central question of the project is how
often this segmenter fails on Kannada, where a single akshara frequently consists of several
components and adjacent characters often touch. The primary metric is therefore the segmentation
success rate. No pretrained OCR models or weights are used.

Results are not reported in this document. The `results/` directory is generated by
`src/evaluate.py`.

## Setup

The project has been tested with Python 3.13 on Windows. All commands are run from the project root.

```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

On Windows, the PyPI build of PyTorch is CPU-only, which is sufficient for local use. GPU training is
done in Google Colab.

The scripts print Kannada text. This works in an interactive terminal, but raises
`UnicodeEncodeError` when output is piped or redirected to a file. Enabling Python's UTF-8 mode in the
terminal avoids this:

```
set PYTHONUTF8=1          (cmd)
$env:PYTHONUTF8 = "1"     (PowerShell)
```

Each core module includes a self-check:

```
python src/akshara.py
python src/preprocess.py
python src/metrics.py
python src/segment.py
python src/models.py
```

All settings are defined in `config.yaml`: paths, image height, charsets, seeds, data split, segmenter,
training and Random Forest parameters.

English recognition is case-insensitive. Labels are lowercased on load and all metrics compare
lowercased text, so `SHOP` and `shop` are treated as the same word.

## Trained Models

Trained model files are not stored in the repository. They are published as release assets on the
[GitHub Releases page](https://github.com/k-vruttika/kannada-english-signboard-ocr/releases) and should
be placed in the `models/` directory. The datasets are distributed separately.

## Workflow

The complete pipeline is listed below in order. Steps marked **Colab** run in a notebook on a T4 GPU;
all other steps run locally.

**1. Obtain the data**

1. Download IIIT5K and place `test/` and `testdata.mat` in `data/public/IIIT5K/`.
2. Download IndicSTR12 `test.zip` and extract it inside `data/public/indicstr12_kannada/`, which
   produces `test/images/` and `test/test_gt.txt`.
3. Optionally, download Chars74K `EnglishImg.tgz` into `data/public/chars74k/`.
4. Optionally, add Chars74K Kannada together with a `kannada_classes.tsv` class map.
5. Locate the download links for MJSynth and the IIIT synthetic Kannada set. These two datasets are
   never downloaded in full, either locally or to Google Drive.
6. Verify the test sets with `python src/datasets.py iiit5k --split test` and
   `python src/datasets.py indicstr12_kannada --split test`.

**2. Annotate and crop the photos**

1. Place the photos in `data/photos/` and annotate them in Label Studio (see
   [Photos and Label Studio](#photos-and-label-studio)).
2. Draw `char` boxes for approximately 50 words per script.
3. Export the annotations as JSON to `data/labelstudio.json`.
4. Run `python src/make_crops.py` and correct any labels it reports. Repeat until no issues remain.

**3. Prepare the Kannada vocabulary and build the charset**

1. Upload the project to Google Drive as `MyDrive/ocr-project` (see
   [Files required on Google Drive](#files-required-on-google-drive)).
2. **Colab**: open `notebooks/train_crnn.ipynb` with `SCRIPT = 'kannada'` and run the cells up to the
   one marked *training reads the public words*. `KANNADA_URL` is already set.
3. Download `data/public/kannada_synth/vocabulary.txt` from Drive to the same path locally.
4. Run `python src/build_charset.py` and review the aksharas it excludes.
5. Upload the new `charsets/kannada.txt` to Drive. All models depend on this file, so steps 4–7 must
   be repeated whenever the charset changes.

**4. Render the training characters**

1. **Colab**: run `notebooks/render_chars.ipynb`. It should print `raqm: True`.
2. Download `data/rendered_kannada.zip` and `data/rendered_english.zip`, delete the existing
   `data/rendered/` directory and extract both archives into it.

**5. Train models A and B**

1. `python src/classical.py --script english`
2. `python src/classical.py --script kannada`
3. Record the two fingerprints printed by these commands.

**6. Train model C**

1. **Colab**: run `notebooks/train_cnn.ipynb` once with `SCRIPT = 'english'` and once with
   `SCRIPT = 'kannada'`.
2. Confirm that each printed fingerprint matches the one from step 5 for the same script. A mismatch
   means A, B and C were not trained on the same characters; in that case, check `char_per_class`, the
   rendered archives, and that Chars74K is present on Drive whenever it is present locally.
3. Download `models/cnn_<script>.pth` and the matching `.json` into `models/`.

**7. Train model D**

1. **Colab**: run `notebooks/train_crnn.ipynb` with `SCRIPT = 'kannada'` to completion. The subset
   archive from step 3 is reused.
2. Before training starts, check how many sampled words have fewer output frames than code points.
3. Each run first pre-trains on the public word images, then fine-tunes on the annotated crops.
4. If `models/crnn_<script>_pretrained.pth` already exists (for example, from a run before annotation
   was complete), the notebook fine-tunes that model rather than pre-training again
   (`REUSE_PRETRAINED`). It stops only if the set of code points in the charset has changed; new
   aksharas composed of known code points are supported.
5. Repeat with `SCRIPT = 'english'` and `MJSYNTH_URL` set. Confirm that the subset contains tens of
   thousands of unique words.
6. Download `models/crnn_<script>.pth` and the matching `.json` into `models/`. The `_pretrained`
   files are optional.

**8. Evaluate**

1. Run `python src/evaluate.py`.
2. Review `results/results.csv` and the generated charts.
3. Fill in the `category` column of `results/errors.csv` manually.

**9. Run the application**

1. Run `python app/app.py` and test several photos from the test split with each model.

### Files required on Google Drive

Drive requires `config.yaml`, `requirements.txt`, `src/`, `notebooks/`, `charsets/` and `data/crops/`,
plus `data/public/chars74k/` if Chars74K is used. `.venv/`, `data/photos/`, `data/rendered/`, `models/`
and the other public datasets are not needed. The notebooks write their archives, models and
`vocabulary.txt` back to Drive.

## Data

All paths below are the defaults from `config.yaml`. If the directories are named differently, update
the configuration rather than moving the files.

### Photos and Label Studio

Shop-sign photos are stored in `data/photos/`, using the same file names as those uploaded to Label
Studio.

Labelling configuration (OCR template):

```xml
<View>
  <Image name="image" value="$ocr"/>
  <Labels name="label" toName="image">
    <Label value="kannada"/>
    <Label value="english"/>
    <Label value="char"/>
  </Labels>
  <Rectangle name="bbox" toName="image"/>
  <TextArea name="transcription" toName="image" editable="true" perRegion="true"/>
</View>
```

- Each word is annotated with one rectangle labelled `kannada` or `english`, with the word entered in
  the transcription field.
- For the boxed subset, each letter or akshara inside the word also receives a rectangle labelled
  `char`. These require no transcription. The number of `char` boxes must equal the number of units in
  the word; `make_crops.py` reports any words where it does not.
- Annotations are exported with **Export → JSON**, not JSON-MIN.

`python src/make_crops.py` writes `data/crops/*.png` and `data/crops/labels.tsv` with the columns
`path, text, script, photo_id, n_units, split, char_boxes`. The data is split 70/30 by photo using the
configured seed, and the test split is never used for training or tuning. `char_boxes` is either empty
or a JSON list of `[x0, y0, x1, y1]` boxes relative to the crop, ordered left to right.

### Public datasets

Sizes are approximate. Where a size is listed as unknown, refer to the dataset's download page.

| Dataset | Purpose | Location | Approx. download |
|---|---|---|---|
| IIIT-Synthetic-IndicSTR-Kannada | CRNN pre-training, charset vocabulary | Colab only; locally, only `vocabulary.txt` in `data/public/kannada_synth/` | unknown |
| IndicSTR12, Kannada subset | Kannada public test set | extract `test.zip` inside `data/public/indicstr12_kannada/`, producing `test/images/` and `test/test_gt.txt` | ~2 MB |
| MJSynth (90kDICT32px) | English CRNN pre-training | Colab only, streamed | full archive ~10 GB; subset a few hundred MB |
| IIIT5K | English public test set | `data/public/IIIT5K/` with `test/` and `testdata.mat` | ~100 MB |
| Chars74K English | additional characters for A–C (optional) | `data/public/chars74k/English/Img/GoodImg/Bmp/Sample001 ...` | ~130 MB (`EnglishImg.tgz` only) |
| Chars74K Kannada | additional characters for A–C (optional) | `data/public/chars74k/Kannada/Img/GoodImg/Bmp/...` plus `kannada_classes.tsv` | unknown |

The Kannada ground-truth files are read as `image_name<TAB>text`, one line per image. If a Chars74K
directory or the Kannada class map is missing, that dataset is skipped with a message.
`kannada_classes.tsv` contains one line per folder, for example `Sample001<TAB>ಅ`. Chars74K has no
official split, so a fixed shuffle is divided 70/30 using the configured seed.

`python src/datasets.py <name> [--split test] [--limit N]` loads any dataset and prints sample entries
and the shape of one batch. Available names: `crops`, `kannada_synth`, `indicstr12_kannada`,
`mjsynth`, `iiit5k`, `chars74k_english` and `chars74k_kannada`.

### Handling the large datasets on Colab

Google Drive does not have enough space for the full Kannada synthetic set or MJSynth.
`notebooks/train_crnn.ipynb` downloads and extracts them only on the Colab disk (`/content`), then
archives a random subset of `SUBSET` words (200,000 by default) to Drive as
`data/public/<set>_subset.zip`. Later sessions extract this archive directly, and training always reads
from `/content`.

- **MJSynth.** `src/mjsynth_subset.py` streams the `.tar.gz` and stops after `SUBSET` readable images.
  It writes an annotation file in the original format and reports the number of unique words retained.
  A very low count indicates that the archive is ordered by word; in that case, delete the archive and
  add `--every 45` to the command in that cell. The script then streams the entire archive once and
  keeps every 45th image. The download link is available at https://www.robots.ox.ac.uk/~vgg/data/text/.
- **Kannada synthetic set.** The link and paths are preconfigured in the notebook. The 4.6 GB archive
  is downloaded with `wget -c`, which displays progress and can resume within the same Colab session.
  Only `train/train_gt.txt` and `train/vocabulary.txt` are extracted from it. `src/subset_words.py --zip`
  then selects `SUBSET` random words and extracts only their images, so the 2 million images are never
  fully unpacked. The notebook then copies `vocabulary.txt` to Drive for `build_charset.py`. These steps
  do not require a GPU and can be run on a CPU runtime first.

### Kannada charset

`python src/build_charset.py` counts aksharas in `vocabulary.txt` and in the **train** split of
`labels.tsv`, counting each vocabulary word once. It keeps the most frequent aksharas that together
cover `charset_coverage` (0.99) of all occurrences, writes them to `charsets/kannada.txt`, and reports
those excluded. For models A–C, any akshara outside the charset is mapped to the class `<rare>`. The
CRNN uses a separate alphabet: the script also writes every Kannada code point found to
`charsets/kannada_alphabet.txt`, regardless of coverage. It additionally reports the number of classes
retained at 0.95, 0.97, 0.98 and 0.99 coverage, along with an estimated Kannada Random Forest memory
footprint for each. The English charset consists of `a–z`, `0–9` and `&`, and the English CRNN uses the
same file.

## Training

### Models A and B: HOG + SVM and HOG + Random Forest (local)

Kannada rendering requires Pillow's RAQM layout engine, which is usually unavailable in Pillow on
Windows. The training characters are therefore rendered in Colab with `notebooks/render_chars.ipynb`,
using free fonts (Noto Sans/Serif Kannada, Lohit Kannada, Noto, DejaVu, Liberation). Light rotation,
blur, noise and scaling are applied, and English characters are rendered in both cases.

`python src/classical.py --script <english|kannada>` trains both models on HOG features of 32×32
crops. It uses at most `char_per_class` samples per class and holds out 10% for the reported
validation accuracy. It saves `models/svm_<script>.joblib` and `models/rf_<script>.joblib` and reports
their disk size and approximate memory usage. The forest uses 50 trees with a minimum of 5 samples per
leaf, since scikit-learn stores one value per class in every node. Even with these limits, the Kannada
forest requires approximately 2 GB of RAM.

### Models C and D: CNN and CRNN (Colab, T4 GPU)

`SCRIPT` is set in the second cell of each notebook. Both notebooks import from `src/`, copy their
inputs to `/content`, fix the random seed, use Adam with early stopping on validation loss, and report
the training time. The resulting `.pth` and `.json` files are downloaded into `models/`; the
application and evaluation run them on the CPU.

- **`train_cnn.ipynb`** trains model C on the same characters as A and B, verified by the fingerprint.
- **`train_crnn.ipynb`** trains model D in two stages. It first pre-trains on the public subset,
  holding out 5% for validation, then fine-tunes on the train split of the annotated crops, holding out
  15% of those photos for validation. The network reduces the width by a factor of 4, so each word
  yields `width / 4` output frames. Since CTC cannot learn from words with more code points than frames,
  the notebook counts such words beforehand.

## Evaluation

```
python src/evaluate.py
python src/evaluate.py --scripts kannada --models A B --limit 500
```

The evaluation runs every model found in `models/` on the photo test split, on IndicSTR12 (Kannada)
and on IIIT5K (English). Each model is evaluated without preprocessing, then with CLAHE, sharpening and
deskew applied individually. Missing models or test sets are skipped with a message. `--limit`
evaluates a random subset of each public dataset. Outputs are written to `results/`:

- **`results.csv`** contains one row per model × script × test set × preprocessing method:
  - `seg_success` (A–C): proportion of words whose segment count equals `n_units`.
  - `seg_success_iou`: computed on boxed words only, additionally requiring IoU ≥ 0.5 per segment.
    Left empty for deskew, since deskew rotates the crop away from the box coordinates.
  - `char_acc` (A–C): computed only on correctly segmented words.
  - `cer`: computed over aksharas for Kannada and letters for English; may exceed 100% when a model
    outputs extra units. `wer` and `exact` are the remaining text metrics.
  - `_lo` and `_hi`: 95% bootstrap confidence intervals from 1000 resamples of photos. The public
    datasets resample individual images instead.
  - `rare_share`: proportion of test units outside the charset.
  - `ms_per_word` (CPU), `size_mb` and `train_seconds`: efficiency measures.
- **`errors.csv`** lists up to 25 random failures per model, script and test set.
  `suggested_category` is an automatic initial classification; the final category is assigned manually
  as one of: segmentation failure, confusable characters, dropped vowel sign, split/merged akshara, or
  stylised font.
- **`seg_success_by_script.png`** and **`cer_by_model_script.png`** are based on the photo test split.
- **`confusion_<model>_<script>.png`** covers models A–C on correctly segmented words, showing the 30
  most frequent classes for Kannada and 20 for English. Kannada classes are numbered because Matplotlib
  cannot shape Kannada text; the accompanying `.csv` maps each number to its akshara.
- **`top_confusions_<script>.csv`** lists the 20 most frequent incorrect (true, predicted) pairs for
  each of A–C.

## Application

```
python app/app.py
```

- **Open a photo** via *File → Open image*. Ctrl + mouse wheel zooms, and *Zoom to fit* resets the
  view.
- **Select a word** by dragging a rectangle around it. *Tools → Suggest boxes (MSER)* displays dashed
  candidate boxes that can be clicked to select. This is an aid only and frequently misses words.
- **Run** recognition after choosing a model (A, B, C, D or All), the script and any preprocessing.
  Each model adds a row showing its output text, confidence and recognition time.
- **The preview** shows the segments classified by models A–C.
- **Export** the session's results via *File → Export results to CSV*.

Models are loaded from `models/` on first use. Unavailable models are greyed out and named in the
status bar. Selecting the Kannada Random Forest displays a notice that it requires approximately 2 GB
of RAM. Confidence values are computed differently for each model and should only be compared within
the same model.
